# Troubleshooting

Every error has a stable code. With `--json` it is in `error.code`; the
[command reference](commands.md) lists the exit codes.

## Installation

- **`bladecp: command not found` after `npm install -g`.** The npm global
  `bin` folder is not on your `PATH`. Run `npm prefix -g` and add its `bin`
  folder (on Windows, the folder itself) to `PATH`, or use
  `npx @bladecp/cli <command>`.
- **`EACCES` during a global install.** Your npm global folder belongs to
  another user. Use a Node.js version manager, or set a user-owned prefix with
  `npm config set prefix ~/.npm-global`, instead of installing with `sudo`.
- **Syntax errors or `Unsupported engine`.** The CLI needs Node.js 20 or later.
  Check with `node --version`.

## Sign-in

- **The browser did not open.** Copy the address printed in the terminal, or
  run `bladecp login --no-browser`.
- **Remote server over SSH.** The sign-in page returns to the computer that
  runs the CLI. On a remote server, create a key at
  <https://hub.bladecp.com/account/api-keys> and use `bladecp login --token -`
  or `BLADECP_API_KEY`.
- **"Sign-in timed out" (`login_timeout`).** The CLI waits 5 minutes for the
  browser. Run `bladecp login` again when you are ready.
- **"Your API key was not accepted" (`unauthorized`) or "Your API key has
  expired" (`api_key_expired`).** Run `bladecp login` again, or create a new key
  at <https://hub.bladecp.com/account/api-keys>.
- **"Your account already has the maximum number of active API keys"
  (`api_key_cap_reached`).** Revoke a key you no longer use at
  <https://hub.bladecp.com/account/api-keys> and sign in again.
- **"You are not signed in" (`not_signed_in`) right after signing in.** The
  saved sign-in belongs to the API address it was created for. Check that
  `--api-url` and `BLADECP_API_URL` are not pointing somewhere else.
- **"The configuration file ... is damaged" (`config_invalid`).** Run
  `bladecp logout` and sign in again.
- **"Could not use ...: permission denied" (`filesystem_error`).** The CLI
  could not write to its folder. Check its permissions, or choose another
  folder with `BLADECP_CONFIG_DIR`.

More detail in [authentication](authentication.md).

## Migrations

- **"Choose the destination with --plan and --location"
  (`destination_required`).** Without a terminal the CLI never chooses where
  the site goes. Run `bladecp destinations list`, then pass `--plan` and
  `--location`.
- **"That plan and location are not available for migrations on your
  account" (`destination_unavailable`).** Pick a pair listed by
  `bladecp destinations list`.
- **"Migrations are not open to your account yet" (`commerce_restricted`).**
  Your account cannot start migrations right now. Nothing was changed; reading
  commands keep working.
- **"This is not a .tar.gz backup" (`not_gzip`).** Use the full backup file
  generated by cPanel (for example `cpmove-user.tar.gz`), not a folder or a
  partial export.
- **"The backup is larger than 50 GB" (`file_too_large`).** The limit is 50 GB
  per backup.
- **The upload stopped (`upload_failed`, `network_error`, or Ctrl+C).** Run the
  same `bladecp migrate` command again with the same file. It sends only the
  missing parts.
- **"That domain is already in use on BladeCP" (`domain_unavailable`).**
  Choose another domain with `--domain`.
- **"This action is not available while the migration is in phase ..."
  (`phase_conflict`).** Check the current phase with
  `bladecp migrations status <uuid>`.
- **Exit code 10.** The migration is waiting for you, usually to confirm the
  domain. Run the command shown in the output, for example
  `bladecp migrations review <uuid> --domain example.com`.
- **Exit code 9.** The migration failed or was cancelled. When a retry is
  allowed, the output shows `bladecp migrations retry <uuid>`; when it is not,
  the output says why.
- **A phase is "taking longer than usual".** The migration keeps going on
  BladeCP even if you close the terminal. Follow it later with
  `bladecp migrations status <uuid> --watch`; when it takes much longer, the
  CLI shows the support address.
- **"A migration of this file is already in progress to ..."
  (`migration_in_progress`).** You ran `migrate` again with another `--plan`
  or `--location`. Run it without them to continue, or cancel the earlier
  migration first.
- **"... matches N of your items" (`ambiguous_id`).** Type more characters of
  the ID, or the whole ID.

## Network and limits

- **"Could not reach ..." (`network_error`).** Check your internet connection
  and that HTTPS to `api.bladecp.com` is allowed.
- **"Too many requests" (`rate_limited`).** The CLI already waits and retries;
  if it still fails, wait a minute.
- **"The daily request limit for this key was reached"
  (`daily_quota_exceeded`).** Try again the next day.
- **"Refusing to send your key over plain HTTP" (`insecure_api_url`).** Use an
  `https://` address. Plain HTTP is accepted only for `localhost`.
- **"BladeCP answered in a format this CLI does not understand"
  (`invalid_response`).** Try again in a few minutes; if it keeps happening,
  update the CLI with `bladecp update`.
- **"This version of the BladeCP CLI ... is no longer accepted"
  (`update_required`, exit code 11).** Run `bladecp update`.
- **`bladecp update` fails with a permission error (`update_failed`).** See
  [installation](installation.md#update): give npm a folder you own instead of
  using sudo.
- **To see what the CLI sends,** add `--debug`: each request is described on
  stderr (never the key).

## Get help

Open an [issue](https://github.com/bladecp/bladecp-cli/issues) with the CLI
version (`bladecp --version`), the Node.js version, the operating system, the
command and the error `code`. Never include your API key. Report
vulnerabilities privately as described in [SECURITY.md](../SECURITY.md).
